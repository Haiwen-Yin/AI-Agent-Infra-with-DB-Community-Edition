# v5.0.4 release notes / 发布说明

## English

- Explicit STATUSPAGE sources read a bounded selection of GitHub or Cloudflare
  official incident records through the existing Task-backed synchronization
  flow. Complete overview and update units become pending Knowledge candidates.
  Historical status, distinct announcement/impact times, unknown internal metrics
  and exact source provenance remain explicit. Independent review and applicable
  intake metadata are required before promotion.
- Incident report assets include an adapted Chinese PagerDuty postmortem template,
  factual JSON schema and original license/attribution. Authorized overview
  resolution returns a schema-valid draft bound to its verified snapshot.
  Public incident bodies are not bundled as tenant Knowledge.
- Context evidence displays existing budgets, exact revisions, omissions and
  input receipts. Current authorization also applies to omitted-source metadata.
  Input observations do not establish answer success or provider usage.
- The common native transport inspects final text fields after Provider conversion
  and serializes the inspected request once. Its byte receipt covers tool/schema
  and Provider fields; managed image pixels remain outside semantic inspection.
- Migration 119 extends the existing Source kind constraint on each backend;
  PostgreSQL migration 120 repairs both historical native constraint forms.
  Upgrade verification recognizes valid stable-installation lineage and retains
  exact checksums and native predecessor checks.
- The installation matrix covers five artifacts and seven database targets,
  with fresh installation and actual v5.0.3 upgrade paths. Final byte differences
  are reviewed against retained executions and affected regression checks.
- Native mixed-retrieval measurements preserve current authorization and existing
  query-scope Embedding reuse. No query/TTL cache or automatic shared encoding
  is enabled; no Token, cost or general performance improvement is claimed.
- Generated prose still requires review: the tested model sometimes attributes
  locally derived missing fields to the upstream provider. The factual report
  remains a draft; unknown internal impact and unapproved advice remain explicit.
  Targeted model checks do not establish complete Portal/Channel answer quality.

## 中文

- 新增显式配置的 STATUSPAGE 来源，在既有 Task 同步流程中有界读取 GitHub 或
  Cloudflare 官方故障公告。完整概览和逐条更新形成待审核知识候选，保留历史状态、
  公告/影响时间区别、未知内部指标及精确来源。发布前仍需适用元数据和独立审核。
- 提供参考 PagerDuty 的中文复盘模板、事实 JSON schema、原始许可证与署名；
  概览来源的授权解析返回与已核验快照绑定、符合 schema 的事实草稿。
  不将公开事件正文预置为租户知识。
- 上下文依据页面展示已有预算、精确修订、遗漏和输入回执；遗漏来源的元数据同样
  受当前权限约束。输入记录不代表回答成功或供应商用量。
- 公共原生传输在 Provider 转换完成后检查最终文本字段，并一次序列化实际请求。
  字节回执覆盖工具/schema 和 Provider 字段；不声称检查了托管图片的像素语义。
- 三种底座以增量迁移 119 扩展 Source 类型约束；PG 120 兼容历史约束的两种原生
  表达。升级检查识别合法稳定安装的版本链，继续要求精确摘要和原生前序结构。
- 安装矩阵覆盖五个交付物、七个数据库目标的新装及实际 v5.0.3 升级。最终字节
  差异与原执行记录、受影响回归分别绑定，不把历史执行改称最终包执行。
- 三库混合检索实测保留当前授权及已有 query scope 内的 Embedding 复用。
  未启用 query/TTL 缓存或自动共享编码，不宣称 Token、费用或普遍性能收益。
- 生成文字仍需审核：本轮模型有时把本地报告缺失字段归为官方字段。事实报告
  继续是草稿，内部影响保持未知，建议未经批准。专项模型检查不代表完整
  Portal/Channel 回答质量验收。
