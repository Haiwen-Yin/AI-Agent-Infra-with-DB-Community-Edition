# 官方事件来源与复盘草稿

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

在 Agent 上下文资产的来源配置中选择 STATUSPAGE，可选 GitHub 或 Cloudflare 官方
故障公告。路径 `/incidents/recent/N` 读取最近 1–5 个事件；使用 JSON，无需凭据。
显式创建同步任务后手动执行。默认不启用定时采集。

一次读取只覆盖官方 API 返回的近期页面，不代表完整历史。同步保留单事件修订、
完整概览与逐条更新；未变事件复用既有修订。失败不会推进成功检查点，也不把缺失
事件解释为删除或已解决。超过单元或总量限制时需要明确整理，系统不会任意截断正文。

每个单元进入待审核知识候选，默认为 HISTORICAL。配置来源或同步成功都不会自动
发布知识。发布前需要补全用途、责任主体、适用范围、分类与受众等引导信息，由独立
主体审核并显式提升。AI 审核仍是 AI 审核，不等同于人工批准。

概览的授权来源解析包含匹配随包 `report.schema.json` 的 `factual_report`。它绑定实际
Task 读取的响应摘要、单事件摘要与观测时间，保留 display_at、created_at、started_at
等不同时间字段。上游影响标签不是本企业 SEV；两个时间字段之差不是本企业 MTTR
或 SLA 损失。根因、内部受影响用户和严重性保持未知，后续建议尚未批准。

这些缺失字段属于本地事实投影，不能据此认定官方 API 存在同名空字段，或已证明
相关事实不存在。生成摘要需要核对来源：本轮模型仍有混淆这一归属的措辞。阶段性
更新属于历史记录，操作前应核对最后记录的状态与观测时间。

完整中文复盘模板、署名和原始许可证位于随包 `docs/enterprise-incidents/`。
模板改编自固定版本的 PagerDuty 开放模板。官方事件正文并未获得概括性的再分发
许可，不随产品预置成租户知识。远端正文始终是需核验的来源数据。

当前来源授权继续约束精确读取、候选审核与上下文使用。撤销来源后，旧引用不会
绕过当前权限；对已经不可读的遗漏来源，上下文依据页也不再暴露其历史标识。
