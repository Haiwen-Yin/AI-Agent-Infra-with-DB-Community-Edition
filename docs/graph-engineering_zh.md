# 图工程 v5.0.0

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

[English](graph-engineering.md)

## 执行模型

图工程通过版本化、数据库持久化的执行图，协调 Agent、Model、Skill、Tool、Database、Human、Event 与 Subgraph 节点。定义、不可变的已发布版本、编译计划、运行、节点运行、尝试、状态事件、检查点、制品和治理事件各有独立关系实体。实体关系图是另一种投影，界面上的一条边不代表执行授权。

本产品支持 oracle, pg, yashandb。单库包只包含对应适配器，整合社区包每个进程选择一个底座。运行合同复用所选数据库的事务和约束，厂商图语法留在适配层。Oracle、YashanDB 原生属性图及 PostgreSQL AGE 都是可重建投影；原生投影未更新时，仍可通过授权后的关系查询读取。PostgreSQL 历史文本边端点按文本比较，不能直接强制转换为 BIGINT。

## 能力状态

| 功能 | 默认状态与操作范围 |
|---|---|
| 运行核心与授权检查 | 按当前权限使用 |
| 清单草稿导入、只读 SLO、检查点分叉 | 受控，须检查证据及能力状态 |
| 离线回放、迁移预检 | 仅限有界检查，不触发远端副作用或移动活动运行 |
| 已登记 MCP、A2A、OTLP、固定框架执行 | 独立受控入口，明确授权前关闭 |
| 任意框架、远端副作用回放、动态图在线迁移 | 未开放 |

在“平台配置 → 图工程配置”检查数据库中的当前能力矩阵。发行配置、提示词、Agent Card 或隐藏按钮均不能改变能力状态。[Agent 扩展](agent-extensions_zh.md)列出具体协议版本及操作范围。受约束的 A2A 合同已实现任务状态 SSE 订阅，不代表支持完整 SDK、gRPC 或推送。

## 从定义到运行

1. 创建草稿，明确所有者、目的、节点、边、结构、预算和副作用分类。
2. 编译该确切版本，检查未解析执行器、无效路由、结构不兼容和预算诊断。
3. 通过授权服务发布。供应链导入始终生成新草稿；不可信草稿不能仅因解析成功就发布。
4. 根据已发布版本及匹配的编译计划启动运行，记录定义及计划摘要、兼容级别和结构版本。
5. 检查节点运行、已提交状态、追踪、尝试、检查点和干预决策；暂停、恢复、取消和恢复处理均须具备当前权限。

使用 Dashboard 图视图或已认证 API，不直接修改表。[API 参考](api-reference_zh.md)说明接口，[连续性操作](continuity-operations_zh.md)说明关联工作和上下文流程。

## Worker 与恢复

Worker 声明支持的执行器，领取有界工作，并获得短期租约和围栏令牌。心跳、检查点和完成操作必须匹配当前权限；过期 Worker 不能提交。可执行节点必须解析为内置或已登记的声明式执行器，拒绝任意代码字段。

状态事件只追加。检查点保存可恢复状态，不能覆盖后来的权限撤销。替换进程重新向同一数据库校验身份、来源权限和租约。等待协作关卡不占用 Worker 租约。

相同请求在平台领取和完成边界保持幂等，不代表任意远端副作用都能恰好执行一次。`IDEMPOTENT_EXTERNAL` 尝试保存稳定逻辑效果键，供支持去重的远端服务使用。`NON_IDEMPOTENT` 或结果不确定的操作需要外部状态确认、补偿或人工处理；不能自动重发未观测到结果的模型或工具调用。

检查点分叉保留来源并创建独立子运行。含不可重复效果的子运行暂停，直到记录必要决策。动态提案创建新草稿版本并生成确定性风险判断，不改写已发布版本，也不迁移活动运行。

## 事件、评估与证据

Inbox/Outbox 保存投递尝试、重试计划和 `DEAD_LETTER` 状态。重放必须提供原因，并遵守当前操作合同。评估器支持 `MANUAL`、`TEST`、`DIFF`、`LLM_JUDGE`、`SPEC_VALIDATION` 和 `AGGREGATE`。评估结果是可归属、版本化的决策证据，不能自行授权工具或模型调用。

管理员通过 `/api/graph-runs/{run_id}/evidence` 导出运行证据，必须提供原因和有界数量，并记录治理事件。制品保留摘要、分类、保留期和法律保留信息；可见元数据不代表可读正文。指标仅描述所记录负载中的状态迁移、重试、预算与可靠性，不能当作通用容量承诺。

任务计划、步骤、循环和关卡继续保留原有实体。A2A 与 DB4A2A 使用各自传输，关联稳定的任务计划、步骤和带围栏的尝试。DB4A2A 传递受授权的上下文引用、摘要、版本和范围，既不隐含授权，也不代表跨平台 A2A 一致性。详见 [DB4A2A](db4a2a_zh.md)。

## 运维

部署并核验所选底座直到迁移 101 的完整基线，保留已应用 SQL 摘要和迁移历史。升级或恢复前记录活动运行，只排空涉及的写入进程。按[恢复](recovery_zh.md)与[迁移](migration_zh.md)指南处理。同一数据库下的进程替换不能证明数据库集群高可用、备库提升或 RPO/RTO。
