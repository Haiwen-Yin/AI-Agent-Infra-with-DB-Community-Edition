## 启动与登录

单一 FastAPI/Uvicorn 入口 `web_app:app` 提供 `/app` Dashboard、`/portal` 及已认证兼容路由。在完成初始化的包中执行 `bash start_web_server.sh start`；使用 `status`、`stop`、`restart` 或 `log` 管理该实例。停止前先核对目录与端口。配置和外部访问要求见[部署指南](deployment_zh.md)。

Dashboard 与 Portal 分别保存会话。两个登录页面可以相互进入，并按当前人用户注册策略显示注册入口。外部 Agent 注册有独立策略与生命周期。产品没有通用默认管理员密码；密码错误与已登录会话过期分别提示。

界面支持中英文、浅色和深色主题，名称、Logo、版本类别、数据库范围和版本号来自当前安装产品。OpenTenBase AgentX 使用独立身份，仅支持 PostgreSQL。川序中文名称使用原始矢量艺术字。导航按顺序平均分为两行；窄屏时每行独立横向滚动，第一项仍可访问。

## Dashboard 页面

页面根据服务端能力与当前权限过滤。隐藏按钮不能替代授权检查。

| 路由 | 主要操作 |
|---|---|
| `/app/monitor` | 平台活动与状态 |
| `/app/wallboard` | 已认证只读运营看板、Token/费用趋势与数据时效 |
| `/app/agents` | 外部及原生 Agent 清单、生命周期和归属 |
| `/app/tasks` | 任务计划、步骤、状态与执行关联 |
| `/app/workspaces` | 工作区和工作连续性 |
| `/app/knowledge` | 获准知识清单、详情与可见范围 |
| `/app/memory` | 记忆族、版本与生命周期 |
| `/app/skills` | Skill 与工具目录 |
| `/app/specs`、`/app/branches`、`/app/loops` | 规格、分支与迭代工作 |
| `/app/graph` | 实体关系图、图定义、运行与诊断 |
| `/app/channels`、`/app/barriers` | 可归属的讨论和协作决策 |
| `/app/users`、`/app/organization`、`/app/security-domains` | 人员、责任层级与协作授权 |
| `/app/platform` | 能力策略、部署、模型与运行管理 |
| `/app/approvals`、`/app/compliance`、`/app/audit` | 企业版许可范围内的治理视图 |

使用 `/app/workspaces?view=continuity` 处理契约、交接、上下文组装、候选和诊断；使用 `/app/skills?view=tools` 查看、导入并显式开放工具。完整流程见[连续性操作](continuity-operations_zh.md)和 [Agent 扩展](agent-extensions_zh.md)。

## 人员、Agent 与频道

主体选择器按名称、用户名和类型显示候选，提交确切不可变 ID。同名时须核对类型和用户名。候选列表以有界浮层显示，不推动周围表单；支持键盘、重试、分页、移除和过期搜索取消。仅输入搜索文字不能满足必选要求。

先授予频道所属安全域的成员资格，再到频道管理中搜索并添加成员。候选排除过期、停用和已有成员。讨论线程只组织上下文，不添加成员，也不授予知识、模型、Skill 或 Tool 权限。线程、现有成员和添加成员分别分块。

显式 @ Agent 要求其为合格、激活的频道成员，并具备已批准模型、部署目标和模板要求的隔离。平台 Agent 保留英文显示名用于 @；企业版另有独立合规 Agent。提案、执行排队、回答完成与派发失败是不同状态。流式回复更新同一消息行，并尊重用户手动滚动位置。

## Portal

Portal 从可用池分配合格的本地托管 Agent，外部 Agent 注册不向 Portal 提供可用池。用户和已分配 Agent 必须同时有权读取知识来源。命中知识的回答带引用；策略允许时，通用模型补充单独标注来源。歧义或无关问题不能直接复制无关产品知识作为回答。

用户可创建会话、选择获准模型、查看授权知识、进入工作连续性页面并释放 Agent。退出或注销会释放连接及占用名额；会话按服务端租约到期。详见[频道与知识回答](channel-knowledge_zh.md)。

## 平台配置

能力开关、图工程状态、外部注册和会话策略有独立子页面。运行管理包括服务商配置、模型用量、Admin Agent 接入与管理、Agent Pool、签名升级及 Skill 分发、紧急阻断。部署页面包含模型与 Embedding 配置。

直连与网关开关相互独立。草稿修改须显式确认并提供原因；平台生成的转发地址只读。健康状态要求真实观测到配置模型的有效回答。运营看板没有写入控件，区分空数据、过期、不可用和部分观测用量。

标签、提示与按钮应留在各自框体中。密集治理详情使用宽抽屉，窄屏缩为单列。长名称和 ID 在对应控件内换行或滚动，不能仅隐藏溢出来掩盖布局问题。可见状态值均使用本地化标签。

## API、安全与诊断

新客户端使用 [API 参考](api-reference_zh.md)中的已认证 `/api/auth/*`、资源和 Gateway 合同。`/api/health` 报告进程与版本，`/api/ready` 检查数据库及控制面就绪；不可用时返回 503。兼容处理器在同一进程和授权边界内运行，不另启服务器。

图遍历使用所选适配器和当前可见性策略，不能把 Oracle 专有语法写成所有数据库的要求。关系边不是数据授权。

登录后界面重新加载当前会话和 CSRF 状态。HTML 与控制面资源使用 no-store 缓存策略，避免升级后仍运行旧资源。故障记录产品、版本、路由、语言、视口和脱敏错误，不把会话 Cookie、密码或原始配置放入截图和支持报告。发布截图必须显示加载完成的当前已登录页面，并将后端版本和实际资源摘要关联到同一发行包。
