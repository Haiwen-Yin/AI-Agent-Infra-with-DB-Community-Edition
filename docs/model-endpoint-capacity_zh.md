# 共享模型容量与请求观测

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

同一个模型资源使用同一个数据库协调器，保存有版本的容量策略、参与身份、
模型 Profile 绑定及服务地址别名。默认容量为 1。同一推理资源的其他地址也应登记
在同一组中；新建 Profile 指向已登记地址时仍需准入，改名不能绕过队列。

在 **平台配置 → LLM 服务商配置 → 共享模型容量** 中登记资源、请求主体和已保存
的模型配置，查看请求或修改策略。刷新只读数据库状态，不调用模型。这些操作需要
当前模型网关管理权限，只读会话不能修改。功能依赖 v5.0.2 运行契约和迁移 106，
仅更新浏览器文件不会启用。

## 协调范围

参与进程必须共享同一个权威协调器。其他安装通过其模型网关接入，并登记真实认证
身份。各自数据库中的锁不能组成全局队列。受控资源会在不支持的旧直连入口或未保存
配置的草稿探测中被发送前拒绝，应改用已保存、经过认证的 Profile 入口。
不在受支持观测路径中的外部调用仍属于未观测流量。

跨数据库接入时，管理员先在协调器登记参与方和已保存的上游 Profile，再通过
`POST /api/model-gateway/coordinator-bindings` 绑定容量组及策略版本、参与方和安装
身份、原始 Gateway 凭据、上游及请求发起方各自的 Profile 版本。在请求发起方，
将 Profile 的地址保存为固定入口 `/api/model-gateway/coordinator/{binding_id}`，
使用已登记的 Gateway 凭据，并通过 `POST /api/model-gateway/coordinator-routes`
登记路由。修改 Profile 或容量策略后必须明确选择匹配的登记；更换 URL 不会自动
恢复直连。机器凭据保存在加密配置中。

请求发起方负责原业务来源的授权：先预留中央容量，再在本地同一事务中复查原始
凭据、来源及 Worker fence，为那一个请求内容和预留签发短期证明。协调器验证
登记身份、自己的容量及上游权限。两边都不会声称能替另一数据库授权其私有来源；
不接受调用方提供的回调地址，也不在协调失败后自动改走直连。

原生和频道 Worker、Portal 回答、托管输入、答案验收、回顾、精确输出契约探测及
模型网关都保留原始业务请求和凭据。发送前复查 Profile、主体、凭据、资源访问、
来源披露及 Worker 租约与 fencing。重新签发凭据不能替代已撤销的原凭据。
后台 Worker 遇到容量排队时取消未发送的准入并以失败退出，不持有业务租约长等。

## 完成、取消与未知发送

排队及尚未使用的预留可以在未发送模型请求时取消。发送后关闭客户端连接只证明
本地取消，不能证明远端生成停止。结果未知的请求继续占用容量；发送租约过期不会
自动释放或允许重试。排队、连接读取、流空闲与整体超时分别保留自己的含义。

可信的完整响应可以结束传输占用，即使业务输出因拒答、截断或校验失败而被拒绝。
管理员核实那个原始请求已结束后，可另行记录人工处理。操作绑定准入、attempt、
fence 和当前版本；HTTP 接口记录的是**人工确认**，不能自称已独立观测远端终止。
失败和未知证据持续保留。此流程不会发起空闲生成探测。

跨数据库请求可通过 `GET /api/model-gateway/origin-requests/{receipt_id}` 读取原始
本地回执，再向其 `/reconcile` 入口明确提交预期版本、原因和幂等键。此操作仅用
原登记凭据读取固定协调器，随后复查本地业务权限并保存独立、不可变的处理记录。
中央请求仍未解决时，本地继续保持未知；本地人工确认不能释放中央占用。
管理员确认传输已终止也不能代表模型响应完整或业务成功，历史未知用量不会改变。
Task 恢复仍需这个精确传输证据，以及自身独立、经过授权的重试决定。

## 时长与用量

执行进度和模型元数据使用相同的准入及原业务 attempt 标识。页面分别显示客户端
观测的排队、发送到首段回答内容、本地模型请求及总请求时长。非流式响应的首内容
时间保持未观测；没有端点证据时，不推算模型内部 prefill 或 decode。
这些时长不能证明答案正确或远端已终止。

输入、输出、缓存读取、缓存写入和推理 token 保留测量值及来源。缓存和推理明细不
重复加进总量；缺失保持未观测，实际报告的 0 保持 0。输入与输出相加得到的总量
单独注明。拒答或截断仍可携带实际报告的用量；未知发送保留不完整用量记录。

模型网关的用量、明细和配额结算在同一事务中绑定原始授权请求。重复处理返回原结算
标识，冲突值会被拒绝。原生 dispatch 元数据是观测，不给同一个网关请求再收费。
重放快照保存失败不会释放或重复计算已结算的消耗。现有定价没有缓存写入费率时，
观察到缓存写入用量会使费用保持未知。容量恢复也不会改写历史未知用量。

请求发起方保存有界、不可变的观测，关联本地回执和中央请求、准入标识。计数来自
经过认证的协调器的实际响应观测，供原业务诊断读取，不会再结算一次，也不暴露
提示词、回答正文或上游凭据。

元数据不保存提示词、答案、凭据或隐藏推理正文。业务详情在读取观测前重新检查原
资源权限，不声称覆盖任意外部直连流量。
