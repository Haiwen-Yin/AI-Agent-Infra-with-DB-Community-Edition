# 组织治理 — AI Agent Infra with DB v5.0.0

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

[English](organization-governance.md)

平台从 v4.3.1 起提供以数据库为准的组织模型，以及用于搜索、检查和准备受控变更的图形工作区。
这是一项稳定能力，无需启用图工程预览配置。

## 权限模型

- 普通平台账户、Human 主体和组织人员是同一主体。每人只有一个有效主组织，可以有多个带有效期的兼任组织关系。
- 注册审批选择主组织，并在同一事务中创建账户与组织关系。没有有效登录身份的主体不能成为组织成员。
- 受保护的初始 `admin` 是系统恢复账户，不进入自然人组织层级。
- 每人最多有一位有效直属上级；虚线汇报与项目负责人关系带有效期，不扩大权限。
- 每个受管 Agent 保留一位有效 Human `PRIMARY_OWNER`。责任组织、群组、操作人和查看者补充责任分工，不替代主要负责人。
- `ORG_SUBTREE` 根据 `CX_ORGANIZATION_CLOSURE` 和主组织关系判定；`DIRECT_REPORTS` 根据正式直属汇报关系判定。安全域范围与组织范围同时适用时取交集。
- 关系表中的事实是授权依据；属性图和 Web 画布是权限过滤后可替换的投影。

## 图形工作区

组织页面提供确定性层级布局、按需加载子树、有界搜索、横纵方向切换，以及组织、人员分配、
Agent 责任和异常四种授权视图。拖动组织只在草稿中提出父级变更；不保存布局坐标，受控发布成功前不修改正式组织记录。

移动端适合搜索、聚焦查看、历史检查和审批；复杂拖动编辑使用桌面端。

## 变更生命周期

变更保存在 `CX_ORG_CHANGESETS` 和有序语义操作中。草稿包含原因、幂等键、基础组织版本、
行版本检查、风险分级、校验结果和影响摘要。撤销与重做只改变操作状态。校验覆盖版本冲突、
父级缺失、环路、作用范围和目标可见性。提交后冻结已校验草稿，并在同一事务中向统一审批
队列创建一个 `ORGANIZATION_CHANGE` 项；重复提交返回已有待审批项。

低风险发布在同一事务中更新当前事实、按需重建组织闭包、写入不可变版本历史、递增受影响
主体的权限版本，并撤销相关 Human 会话和 Agent 访问令牌。高风险变更必须审批，不能走直接
发布。组织页面仅对 `VALIDATED` 且低风险的变更显示直接发布。作者可撤回
`PENDING_APPROVAL` 请求：记录原因并关闭待审批项，原变更保持原操作并回到 `VALIDATED`。
早期非原子提交留下的待审批变更可能缺少审批记录，只有原作者可通过撤回恢复，并生成
`ORG_CHANGESET_WITHDRAW_ORPHAN_RECOVERY` 证据。

创建子组织时，先新建变更集，选择“创建组织”，在“父组织”中选现有组织，再填写新组织名称、
可选 ID/代码和类型。父组织 ID 不会复用为子组织 ID。在“新建变更集”模式中，刷新列表不会
自动选中旧草稿；首次“加入草稿”创建独立变更集并要求单独填写原因。明确选择已有变更集会
退出该模式。草稿冲突、范围或权限不足会显示具体可处理的信息。

新组织 ID 可留空，由服务端生成唯一 ID。Web 与 API 保留空值，父组织标识单独传递，不能
作为子组织标识的后备值。手工指定 ID 时，服务立即检查当前组织和同一草稿中的有效操作，
在加入草稿前拒绝重复 ID 和组织以自身为父级的关系。

“撤销”仅停用最后一项语义操作。“删除草稿”是未发布的 `DRAFT` 或 `VALIDATED` 变更的终止
操作：必须填写原因，记录 `CANCELLED`，保留操作用于审计，并从未完成变更选择器中移除。
“校验并提交”先完成校验和影响分析，成功后才创建审批请求。

审批人需要 `organizations.changes.approve` 并填写原因。普通审批人不能是作者。受保护的初始
`admin` 是唯一紧急例外，其身份由有效本地登录和数据库中的 `BOOTSTRAP_ADMIN` 角色共同
确认；它可以决定自己的请求，但会生成专门的应急审计。仅有 `SYSTEM_ADMIN` 不具备此例外。
审批和发布属于同一事务：组织变更、闭包、类型化历史、子树权限失效、审批和变更终态及审计
要么全部提交，要么全部回滚。拒绝同样原子关闭两条记录，不修改正式组织事实。

## 目录暂存

手工、CSV 和 JSON 输入规范化为有数量上限的暂存批次。角色、权限、安全域、Agent 关系、
密码与秘密等受保护字段会从输入中丢弃。LDAP 属于 Enterprise 连接器范围；OIDC 和 SCIM
只是保留的结构取值，不能宣传为已启用连接器。

未解决的同步冲突保留为可见的治理事项，不能仅凭目录记录到达就覆盖当前权限。

## 运维检查

启用组织编辑前，运行包内迁移执行器和 `live_db_validator.py`。从 v4.3.1 引入的组织检查覆盖
迁移账本、必需列、闭包与历史表、唯一索引、角色模板及数据库专用控制。缺少组织对象会使
就绪检查失败，不会通过隐藏页面掩盖问题。

所有 API 都要求数据库会话；变更还要求 CSRF、操作权限和数据库端范围过滤。客户端不能先
加载全企业数据，再自行过滤无权查看的记录。
