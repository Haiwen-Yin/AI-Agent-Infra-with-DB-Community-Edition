# 模型用量网关与运营看板 v5.0.0

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

[English](model-usage-and-wallboard.md)

## 目的与边界

该平台提供可选的模型调用转发路径，以及一个受登录保护、只读的管理看板。网关并非强制要求：LLM 服务商配置（LLM Provider Profile）可以允许直连模式、平台网关模式，或两者兼有。网关证据有助于 Token 和成本归因，但并不能证明未发生直连调用。除非经过验证的适配器报告了相关数据，否则直接流量处于未知状态。

网关和合规 Agent的证据从不授予权限。身份、安全域（Security Domain）成员资格、服务商/模型许可以及平台操作，仍受其现有的以数据库为依据的控制约束。

## 配置模型路由

1. 打开 **平台配置（Platform Configuration）**，然后进入 **平台运行时（Platform Runtime）** 以及 LLM 服务商配置部分。
2. 在用于转发之前，保存并探测（probe）服务商配置。
3. 在配置行中选择 **直接（Direct）**、**平台网关（Platform Gateway）** 或两者。
4. 选择 **确认更改（Confirm change）** 并输入合规原因。

在行数据与其保存状态存在差异之前，确认操作保持禁用状态。转发地址为只读，由平台生成：

```text
<platform-public-base>/api/model-gateway/completions
```

当反向代理、公共 DNS 名称或 HTTPS 终结器更改了应用程序看到的地址时，请在启动服务之前配置外部可达的基础 URL：

```bash
export CX_PUBLIC_BASE_URL="https://platform.example.com"
```

请勿在 `CX_PUBLIC_BASE_URL` 中包含补全路径（completion path）。平台会自动追加该路径。客户端无法通过路由 API 替换此地址。

## 使用与成本事实

对于成功的服务商响应，账本将记录服务商/模型、主体（Principal）及可选的代理（Agent）、在提供时记录的提示/补全/缓存/推理/总 Token 维度、来源、固定精度成本、货币、定价版本、状态、延迟以及有界关联标识符。缺失的最终用量数据将被标记为 `INCOMPLETE`；它不会被静默地估算为服务商的真实值。

提示词、模型响应、服务商授权头、明文服务商密钥、明文网关凭据以及不受限制的服务商负载不会存储在用量账本中。定价具有生效日期。显示的成本是根据匹配的定价记录进行的平台计算，而非服务商发票。

## 配额、重放、财务与外部证据

企业管理员可以为全局、Human、Agent、凭证、Provider Profile、模型、组织、Security Domain 或成本中心范围定义具有生效日期的 Token 或货币配额策略。`HARD` 策略会原子性地预留容量，并在调用服务商前拒绝请求。`WARN` 策略保留警告并继续执行。完成时结算预留；中断时使用所选的释放或保留计费策略；被放弃的预留会过期。

成功的非流式响应可以为相同的参与者、幂等性键和输入摘要进行重放。有界快照使用 AES-GCM 加密。快照和最终请求状态在一个事务中提交，重试永远不会再次调用服务商。提示词不会被复制到快照中。

Provider 发票与平台计算的成本是分开的。导入与摘要绑定且幂等；发票更正和对账是仅追加的事实。企业分配规则具有生效日期，且总和必须恰好为 100%。分配事实是不可变的、幂等的，并与源行或使用量保持平衡。社区版对费用分摊操作返回明确的许可错误。

受信任的外部适配器使用 Ed25519 公钥、版本化轮换、显式撤销、有界范围、有序序列号以及 nonce 重放保护。已验证的事实使用 `EXTERNALLY_VERIFIED` 来源。这并不会使网关外部的调用自动可观察：没有网关事实或签名适配器证据的活动仍然未知。

## 运营看板

`/app/wallboard` 需要正常的认证会话和授权的读取范围。它显示：

- 总数、在线、忙碌和停滞的 Agent；
- 活跃的 Session、正在运行的 Task Plan 和正在运行的 Loop；
- 14 天的 Token 消耗和成本曲线；
- 有界的 provider/model 使用情况和来源；
- 网关覆盖率、生成时间、数据时效以及过期/错误状态。

Business Agent 的总数、在线数和忙碌数使用已授权的 `AGENT_REGISTRY` 范围。来自 `CX_NATIVE_AGENTS` 的平台原生控制平面 Agent 始终包含在平台范围内的总数和在线计数中（并作为 `native_total` / `native_active` 暴露）。没有活动时间戳的原生记录不会被归类为忙碌。业务组织/安全域过滤器不得使平台健康状况显示为零。

组织范围定义通过 Agent 的活跃主要 Human 所有者以及该 Human 当前的组织成员资格/层级闭包来解析 Agent。不要为 Agent Principal 创建组织-人员成员资格。如果无法查询运行时聚合，响应将使用 `partial=true`、`freshness=DEGRADED`、`sources.runtime.status=UNAVAILABLE` 和 null 运行时值。只有成功的查询才能将零报告为当前数据。

当 Agent 创建知识时，相同的当前关系事实会被捕获在 `CX_KNOWLEDGE_CONTEXTS` 中：一条向上的组织链、受管责任组、遗留执行组、选定的共享范围以及快照摘要。知识图谱投影将这些作为上下文节点/边暴露用于解释。它们仅是来源和导航事实；安全域和组织策略检查仍然是授权边界。

运营看板不确认通知、批准工作、导出数据、测试服务商、调用 Agent、保存偏好设置或更改配置。其数据路由仅限 GET。在授权丢失时，受保护的值不得再作为交互式视图可用。

管理员在管理界面上配置运营看板。小部件、维度、布局、刷新间隔和范围选择器使用允许列表。定义版本是不可变的；发布和回滚会追加受治理的发布事实。查看者只能读取当前已发布的授权版本，并且不包含任何变更控制。

每个规范 API 错误都暴露 `code`、`message`、`correlation_id` 和 `retryable`；相同的关联标识符在 `X-Correlation-ID` 中返回。客户端不得从消息文本推断可重试性。

## 操作和故障排除

- 仅在需要代表性数据时，于已批准的 Enterprise 演示或发布测试数据库中运行 `scripts/tools/seed_v410_enterprise_demo_data.py`。该操作是幂等的，并用于对齐 Agent 身份、所有权、注册表、Sessions、Plans 和 Loops；请勿在客户生产数据库中运行。
- 运行时卡片中带有部分/降级横幅的破折号表示运行时源失败。这不等同于当前的零值。
- 当 14 天窗口内不存在已授权的用量时，空曲线是有效的。
- `INCOMPLETE` 表示服务商或流未提供最终用量。
- 仅启用直连模式并不会导致直连调用出现。
- 显示的网关主机错误通常意味着缺少 `CX_PUBLIC_BASE_URL`，或者反向代理未转发原始方案和主机。
- 服务商故障会返回有界错误；内部响应主体和凭据不会中继给客户端。
- 在回滚或路由禁用期间保留用量和请求行，以确保计费和审计证据在内部保持一致。

通过迁移 101 使用当前软件包基线。历史 SQL 保留用于确定性排序、校验和证据以及源码审查；它不是指示停留在其引入版本的指令。v4.4.8 仍处于撤回状态。请参阅 [迁移](migration_zh.md) 以了解受支持的、带账本的升级边界。

## 用量计费合同

聊天补全网关将缓存令牌规范化为输入的子集，将推理令牌规范化为输出的子集。配置的详细费率取代该子集的普通费率；它不是在同一令牌基础上额外收取的费用。缺失的详细费率使用普通费率。缺失的总计或超过总计的详细信息会使计算出的成本未知，以便进行对账。具有独占缓存计数的服务商架构在使用此包含式合同之前需要显式适配器。服务商账单仍然是结算来源。此源更改不会重写现有的账本条目。
