# 企业 IT 事件复盘报告模板

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

版本归属：川序 v5.0.4 研究与开发。报告初始状态：DRAFT。本文件是可人工填写的完整模板；
机器 schema 定义的是公开状态页可确定性生成的事实子集，两者不等同。

参考 PagerDuty 的企业复盘模板中文改编。Copyright 2016 PagerDuty, Inc.；
Apache-2.0，见 [署名及改编说明](ATTRIBUTION.md) 与 [许可证](LICENSE-PagerDuty.txt)。
改编增加证据字段、未知值、时间口径及川序候选审核映射，未沿用其内部工单标签或期限制度。

## 报告信息

| 字段 | 内容 |
| --- | --- |
| 事件编号 / 报告修订 | 待填写；不同企业的事件 ID 应带来源前缀 |
| 事件标题 / 服务 / 环境 | 待填写 |
| 报告负责人 / 复核人 | 待确认；提出人不能独立批准自己的候选 |
| 会议 / 记录 | 待确认；未经授权不安排会议或发送通知 |
| 上游影响标签 / 本企业 SEV | 分别填写；不能自动映射 |
| 证据截止时间 / 生成时间 | 各自保留时区；均不替代事件发生时间 |
| 资料密级 / 受众 / 适用范围 | 由有权责任人确定；公开上游不自动授予内部共享权限 |
| 审核状态 / 川序候选与来源修订 | 待导入、PENDING、已审阅等须有对应回执 |

## 1. 概要与已确认影响

用两三句话说明发生了什么、对哪些服务有何影响、何时恢复。每项事实附证据。
受影响客户数、失败请求比例、收入损失、SLA 损失和内部 SEV 未取得证据时写“未知”。
区分官方状态页陈述、本企业监控观测和推断；不可把状态页整个事件窗口当作本企业不可用时长。

## 2. 事件经过与处置

说明症状、发现方式、临时缓解、实际恢复措施与长期方案。每个关键动作注明
执行主体、结果及证据。状态为 resolved 只能证明上游标记解决，不能说明具体修复内容。

## 3. 根因与促成因素

分别填写已证实根因、促成条件、尚待验证假设和排除依据。采用无责复盘，描述
系统条件与流程。没有官方 RCA 或内部诊断证据时保留未知，不能从事件标题猜测根因。

## 4. 时间线

| 事件时间及其语义 | UTC 时间 | 原时区 / 公告创建时间 | 行为与结果 | 精确证据 |
| --- | --- | --- | --- | --- |
| 影响开始 / 告警 / 发现 / 公告 / 缓解 / 恢复 | 待证实 | 待填写 | 待填写 | 来源 URL、事件/更新 ID、修订、摘要或日志定位 |

保留 `display_at`、`created_at`、`updated_at` 的不同语义。公告可事后回填展示时间。
只在开始与结束都有证据时计算窗口，注明公式；内部检测时长、恢复时长与 SLA 单独计算。

## 5. 响应人员与协作

记录事件指挥、记录人、服务负责人、客户沟通负责人及实际交接。未知者留空。
川序中的 Task、步骤、协作和 DB4A2A 记录可作为证据，平台外人员不能被虚构为平台主体。

## 6. 做得好的地方与改进点

每点给出观察、证据和改进理由；公开状态页通常不足以评价企业内部响应质量。
将建议标为建议，不能写成企业已承诺或已经实施的措施。

## 7. 后续行动

| 编号 | 建议行动及依据 | 责任人 | 截止日期 | 工单 / Task | 验收标准 | 当前状态 |
| --- | --- | --- | --- | --- | --- | --- |
| A1 | 待填写 | 待确认 | 待确认 | 待创建 | 可检验结果 | 尚未批准或分派 |

不得由模板自动发工单、分派人员、执行变更或调整能力默认值。

## 8. 内外部沟通草稿

内部：简述事实、影响、进展和本报告位置。外部：只使用获准披露的事实及已批准行动。
两份均保持草稿，按相应权限审批后发送；复盘知识发布不自动授权外部沟通。

## 9. 证据清单与缺口

列出原始 URL / 事件 ID / 更新 ID、采集时点、原文或响应摘要、来源修订、
逐项引用、许可与使用范围。区分完整原文、人工摘录、AI 辅助整理和确定性派生。

缺口至少检查：根因、内部告警、实际客户影响、具体缓解/修复、责任主体、长期行动。
旧稿保留；补证后产生新修订，经独立复核后再明确提升或共享。
