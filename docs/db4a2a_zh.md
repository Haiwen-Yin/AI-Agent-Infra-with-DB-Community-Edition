# DB4A2A 数据库介导协作 v5.0.0

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

DB4A2A 是该项目的以引用传递上下文的 Agent 协作模式。它并非标准 A2A 的替代品。A2A 或 Agent Protocol 负责处理发现、委派、状态以及小型事件；而数据库上下文平面则承载经过授权的 Knowledge、Memory、Context、Artifact、Graph 和 Branch 事实。

## 统一的任务连续性

当前的 A2A 和 DB4A2A 执行链路复用相同的数据库 Task Plan 和 Step 标识符。传输特定的 task/run/dispatch 标识符保持为类型化引用，其尝试次数、租约令牌、取消操作以及未知结果的核对均持久化在现有的控制平面中。来自一种传输的状态响应不能静默地完成另一种尝试。迟到或过期的完成操作会被隔离（fenced）；不确定的发送必须在授权新发送之前，与其原始摘要进行核对。迁移 101 建立了这种共享关联，而未引入另一个任务引擎。

## 派发契约

一个派发包含 `task_id`、`context_ref`、`snapshot_digest`、`expected_version`、`scope_ref` 和 `branch_policy`。它不应将大型上下文复制到消息中。接收方 Agent 必须使用其自身的 Principal 进行身份验证。Agent Instance、Security Domain、组织、分类、过期时间、隔离（fencing）以及数据库策略是独立的授权关注点；引用或摘要的存在并不能证明它们已被检查。

共享上下文默认是只读的。允许的写入操作会创建一个子分支，其派发记录会记录源引用、快照摘要和预期版本。对于通过数据库中介的派发，版本 1 标识的是规范 JSON 摘要格式，而不是可变的行计数器。该摘要为 `sha256:`，后接对使用 ASCII 转义且无空白分隔符编码的类型化规范 JSON 树的 SHA-256 哈希值。对象键按排序顺序排列；数组保留顺序。数字使用精确的十进制系数/指数规范化，因此 1 和 1.00 一致，而不会将原生 Oracle Decimal 值舍入为浮点数。字符串、布尔值、空值、数字、数组和对象具有不同的标签；非有限或非 JSON 值将被拒绝。`context_snapshot()` 是参考编码器。作用域为 `workspace:<workspace_id>`；源分支必须与上下文行匹配。创建和分叉操作会针对数据库验证这些事实。源上下文仅通过单独的受治理合并操作进行修改。

当对等节点无法访问数据库时，标准的 A2A 有效负载或 Artifact 交换仍然是回退方案。Agent Cards、协议元数据和上下文引用从不授予数据库、Tool、Skill、Model 或导出权限。

## 当前验证边界

分支端点在创建分支或返回现有分支 ID 之前，要求具备操作权限以及发送方/接收方成员关系。非活动状态和只读的派发将被拒绝。失败的分支插入会传播错误，而不是报告生成的 ID 为成功。

派发分支实现会锁定派发和上下文，验证引用，在一个事务中插入原生 `PARALLEL` 分支，链接派发并写入其审计日志。它不会调用单独提交的分叉过程。失败会一起回滚分支和链接。第二个请求等待派发行锁，并在重新检查引用后返回现有分支。这不是不可变快照重放：更改的上下文会被拒绝，而不是被重构。具有任意摘要或作用域的历史信封必须从存储的上下文中重新创建。

参与者检查服务补充数据库隔离。数据库所有者/控制平面访问以及受限的外部 Agent 访问需要单独的负面测试；服务单元测试无法建立数据库策略覆盖。标准 A2A 互操作性也需要其自身的协议测试。

发送方被独立检查：Agent 必须使用其自身的数据库身份读取上下文；活动 Human 必须拥有工作区或持有 `agents.manage.all`，此外还需具备操作权限。在分支重试时，原始发送方会被重新检查。看到接收方并不构成上下文授权。

事务会锁定参与者主体、规范上下文，以及在 YashanDB 上已存在的显式上下文授权，然后进行独立的身份读取。如果共享删除与已授权的锁定操作发生竞争，删除操作将等待该操作完成；一旦删除提交，后续的分支重试将被拒绝。这是有界的序列化，而不是取消已提交的分支或先前读取的数据。组织、委托和本机权限变更仍需单独的并发验证。当前的 YashanDB 上下文视图无法证明遗留实体表或定义者权限包的隔离性。

## 预期收益与边界

面向引用的调度可以减少同平台或同租户 Agent 之间重复的上下文传输、输入 Token 重复、敏感数据副本以及版本漂移。对于跨组织对等方、小消息或无法访问数据库的运行时，它并不自动更快。数据库争用、快照冲突和临时不可用仍然是明确的失败模式。
