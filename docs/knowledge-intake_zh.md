# 知识入库引导

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

正式共享知识沿用已有候选、独立审核与显式晋升流程。上传文件、创建私有笔记、
来源同步成功或保存候选，都不等于正式发布。

在工作连续性页面选择知识候选，填写标题、正文和精确来源的 `family`、
`entity_id`、`revision_id`、`content_digest`。入库信息包括用途、原始来源与章节、
责任人身份、主题、适用产品或业务、版本、生效区间、密级和预期读者。未知项
可以留空并保存待补充候选；不能用入库时间代替生效时间。保留提案、已拒绝和
历史决定的真实状态，不能因观察时间较新就认定其为当前政策。

`POST /api/knowledge-intake/preview` 使用相同候选契约，核对当前安全域与来源
权限，返回缺项建议和有界原文分块，包括 Unicode 字符位置、原文与摘要。
段落、代码围栏和连续表格行保持完整。较长语义块保留给作者检查；拆分时应
保留表头、单位、条件、否定和例外。预览不调用模型、不保存候选、不批准内容。
重复和冲突检查的覆盖范围明确返回；未检查不等于没有冲突。

`POST /api/artifact-candidates` 保存待审核候选。修订保留旧内容与适用信息，
摘要同时绑定两者。有权的独立安全域管理员按精确摘要审核，随后显式晋升。
缺项会阻止批准和晋升；密级需与安全域一致，责任人必须仍为有效域成员。
晋升时重新校验来源、审核者与责任人权限。预期读者只表达意图；晋升后的原生
实体保持私有可见性。共享或跨域发布仍需另行获得当前授权。

Agent 使用 `/api/agent-gateway/continuity` 前缀和当前发现的候选契约。直接
`knowledge_create` 与 Gateway 创建保留为个人私有笔记入口；直接创建共享知识
返回 `KNOWLEDGE_INTAKE_REQUIRED` 并引导使用候选。来源同步继续生成待审核
候选，适用信息不完整时由有权用户修订后再审核。产品内置手册走已有的受信任
包发布与审计流程。

类型化连续性 MCP/CLI 入口提供 `knowledge_intake_preview`，并复用
`candidate_create`、`candidate_revise`、`candidate_review`、`candidate_promote`。
平台手册先用 `learning_discover` 按可选 `role`、`goal` 发现元数据，再将返回的
`entity_id`、`content_digest`（作为 `expected_digest`）交给 `learning_read`。目录不批量返回正文，每次
读取都重验当前产品发布版本与原生来源权限。

内置学习资料同时绑定产品版本和来源快照摘要。同一产品版本的来源文档修正后，
有权管理员通过原有受信任发布流程生成新快照，原快照及其摘要保持不变。只有
未经用户修改的旧原生投影会退出当前检索；用户补充保留原样。重复发布相同
快照不重复入库，已经撤回或被替代的快照不能直接重新激活。来源文档变化但
尚未发布时，学习目录不继续返回旧快照；修正发布后重新发现并使用新的精确引用。

历史知识先只读盘点，不修改正文、授权或历史。无法确定的来源保持未知；后续
修正需要明确补正范围。盘点通过不代表已经补齐信息或完成审核。
