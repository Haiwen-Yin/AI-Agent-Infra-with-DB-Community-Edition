# 处理诊断与恢复

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

处理诊断扩展现有 Task 连续性、Graph、Loop 和 TaskStep 记录。迁移 107
以类型化关系保存精确目标、动作、预算、阻断、恢复回执和核对结果，并沿用原有
调度器。启用运行时前，需要安装所选交付包要求的完整迁移链；缺少必需表时，
操作会停止。

## 如何理解处理详情

经授权的详情展示原始 Task 和真实 attempt、冻结的目标及输入/来源修订、已观察到
的原因、已用预算和恢复状态。详情不包含来源正文、提示词、模型答案或凭据内容。
每次读取都会重新检查原业务资源的当前权限；诊断标识和 Task 关联不增加访问权。

三类状态分别表示：

| 类别 | 示例 | 含义 |
|---|---|---|
| `BLOCKED` | 未匹配、请求超时、Provider 不可用、端点排队、预算耗尽、来源已撤销、等待人工、执行失败 | 已记录的原因阻止当前操作继续。 |
| `DEGRADED` | Embedding 超时、语义检索不可用、获准的文本回退 | 某条路径不可用或发生变化，获准的操作仍可能继续。 |
| `UNKNOWN` | 可能已发送、租约过期、外部结果未知、客户端关闭 | 现有证据不足以确定外部结果。 |

检索路径与匹配结果分别记录。例如 `EMBEDDING_TIMEOUT`、`TEXTUAL`、`EMPTY`
表示语义路径超时后实际执行了文本检索，但没有找到匹配证据。空结果不会抹去
语义路径超时的事实。

读取、刷新和重启不会触发生成、重置预算、修复记录或启用能力。Task 或传输成功
属于生命周期事实；内容批准仍由现有候选/版本流程和独立审核决定。

## 持久预算与计量

可信接入流程在原始预算根冻结服务端策略和摘要。v5.0.2 的初始上限为：32 次请求、
128 步、262144 个已观察 token、3 次等价动作、8 次没有新增持久进展的动作。
HTTP 调用方不能选择初始策略。经授权的恢复只会在同一预算根增加明确、有界的额度。

每个真实持久事件具有稳定动作键。同一事件重放不重复计量，同一键替换内容会被拒绝。
等价工具提议、调用和迭代会计入重复动作限制。新迭代标识、后继 attempt、Graph
分叉和服务重启都不会获得新预算。停止后保留精确目标、原因和计数。

使用现有真实 Task 连续性的适配器，在 fenced attempt 完成或租约过期时记录一个生命周期步骤。
模型运行时 attempt 消耗一次请求额度，本地来源同步不消耗模型请求额度。该额度
用于约束工作接入，与 Provider 已观察请求账本分别记录。Token 仅汇总原始调用者、
来源和真实 Task attempt 完全匹配的不可变观察。Provider 未报告的用量保留为未知；
计数中没有已观察 token 不代表 Provider 实际使用了零 token。Graph 与旧兼容
适配器记录各自的原生事件，避免同一次完成重复计量。

适配器拥有的动作、原生效果、预算、必需诊断和审计在原事务一起提交。
必需审计失败时，整个操作回滚。Token 观察说明用量，不证明答案质量。

## 人工决策与 API

已认证的 Agent 扩展 API 在 `/api/agent-extensions/processing` 下提供以下接口；
部署路由可沿用其现有外层前缀。读取要求 `workspaces.read`；决策要求
`workspaces.write`、活跃 Human 身份和原业务资源的当前权限。上层 HTTP
入口继续执行会话、CSRF 和 Agent scope 检查。

| 方法与相对路径 | 操作 |
|---|---|
| `GET /{continuity_id}?after=...&limit=100` | 读取元数据，每页最多 100 条阻断观察。 |
| `POST /retries` | 受理一次精确、有界的重试并生成回执。 |
| `POST /blocks/{block_id}/reconcile` | 读取原始证据，或记录明确的人工裁定。 |
| `POST /recoveries/{recovery_id}/dispatch` | 请求已安装的原业务适配器派发，body 为空。 |

重试请求包含原始阻断、预期版本、完整冻结目标、原因码、增加的请求/步骤/token
额度、决策摘要和幂等键。过期目标、替换后的修订或同一键下不同的内容会被拒绝。
受理沿用原 canonical Task 关系，创建后继连续性回执，并与必需审计原子提交。
受理本身不会取得 Worker 租约或发送模型请求。

`ACCEPTED`、容量排队、`DISPATCHED`、生命周期完成和内容批准分别表示不同事实。
同一受理请求重放返回原回执。原操作已完成时，系统在重新授权后返回已有结果引用，
不会再次执行。模型和 Agent 不能批准人工恢复决策或调整自身额度。

## 原生适配边界

| 适配器 | 已接入行为 |
|---|---|
| 回顾生成、受控模型工具阶段、答案质量评估、来源同步 | 真实 Task claim 冻结计量。显式恢复将原任务绑定到相同 Task 和预算的 successor，由原运行器复用原始不可变输入、来源版本和凭据执行；完成、失败与过期记录用量和类型化原因。 |
| 原生执行与频道执行 | 入队创建真实规范 Task 和预算。Worker claim 同事务绑定原生 fence 与真实 Task attempt；每个 Provider 事件有独立不可变的 NMA→Task 映射。显式恢复将原 execution 重新入队，原 Worker 在发送前重查原凭据、来源、Profile 和 fence。 |
| Graph | 每个真实 Graph attempt 对应独立的真实 Task attempt，并绑定 run/node/attempt 原生元组；子项与分叉共享原预算。`SIDE_EFFECT_CLASS=NONE` 的纯 Graph 恢复可通过原 Graph 运行时派发。 |
| Loop 与 TaskStep | 原生迭代、步骤、已记录工具调用与真实 Task attempt、计量同事务提交；resume 检查相同预算和未知结果闸门；运行中的步骤不能替换定义及输入。 |
| 本地 DB4A2A 分支创建 | 不可变 dispatch 修订、精确分支请求、独立 Task attempt、本地分支效果和共享预算计量同事务提交；重放返回已有分支。 |

已安装的恢复适配器覆盖原生 execution、频道、回顾、受控模型阶段、评估和来源同步
运行器。入队先提交，再运行；最终 Provider 接入记录派发。重复入队或派发返回同一
回执。原凭据缺失或授权变化会阻止恢复。含外部副作用的 Graph 需要匹配的容量
适配器，不能使用纯 Graph 路径。其他不支持的目标返回
`RECOVERY_DISPATCH_ADAPTER_REQUIRED` 并保持已受理，不替换任何执行身份。

没有显式上下文、框架或频道安全域的原生执行使用类型化内部计量锚点。它不出现在
安全域目录中，不能添加成员或频道，也不授予协作权限。历史 Task 外键需要注册表
记录时，同一原生 ID 仅增加 `DORMANT` 元数据投影，不创建外部注册、数据库账号、
角色或凭据，且不能作为外部 Agent 注册、激活或认证。现有注册表身份保持原样。

上下文绑定执行的显式恢复重新读取相同、当前仍获授权的 assembly 和来源。新的
尝试由 Task successor 与 Provider 事件留证，原始一次性上下文回执作为历史保留。
assembly 过期或来源撤权仍会阻止交付。

旧 Loop 评估器访问受控模型端点时，必须有可信模型接入适配器；缺失时会在发送前以
`PROCESSING_MODEL_ADAPTER_REQUIRED` 停止。未受控的历史端点保留原评估权限
和执行路径。旧记录 API 对可信原生记录计量，不能独立观察调用方提交记录之前的
外部行为。本地 DB4A2A 分支创建同样只证明该本地效果，不证明远程 Agent 已完成。

## 未知结果与端点容量

超时、客户端关闭或本地租约过期不能证明 Provider 已停止。真实 Task attempt
转为 `UNOBSERVED`，过期 Worker 仍受 fencing 限制，下一次发送被阻止。
系统不会发送探测性生成请求来判断模型是否空闲。

核对必须绑定原业务键、摘要、目标和真实 attempt。`READ_ORIGINAL` 使用可信
原始读取器；本地未知记录仍然保持未知。Graph 读取器只有在精确原生 attempt
成功、完成摘要和 checkpoint 一致时才能证明本地成功。仅有失败或 stale Graph
记录不足以证明外部已终止。

`OPERATOR_RESOLUTION` 以该证据类型保存经授权 Human 的明确裁定。HTTP
调用方不能提交 `TERMINAL_RESPONSE`、Provider 证明标志或自称的请求完成字段。
裁定本身不发送重试。如果匹配的端点 admission 仍为 `UNKNOWN`，可信处理适配器
在同一事务内核对其容量生命周期，并要求当前容量管理员权限、原 capacity attempt、
版本与 fence 一致。必需审计失败时，容量和 Task 裁定一起回滚。

使用已注册远程协调器时，先在协调权威端核对容量，再显式调用
`POST /api/model-gateway/origin-requests/{receipt_id}/reconcile` 读取原 Origin
回执。服务在远程读取前后重查原业务来源、凭据、路由、Profile 和 Worker fence；
不会跨 HTTP 持有本地数据库事务。精确中央终态证据形成独立不可变 Origin resolution，
原 UNKNOWN 回执及观察保持不变。本地 Human 裁定不能释放仍未知的远程槽位。
处理链读取该 resolution 后可将原 attempt 收敛为失败，再经显式决策重试；传输终止
不证明业务成功或内容通过。

原生进度在相同原 execution 授权下返回本地与 Origin 观察。Task 预算只计入完整、
精确匹配的 Origin 用量一次；缺少 usage 或结果未知时，不编造 token 数值。

精确终态核对完成后，已完成工作返回持久结果，或允许新的有界决策。
同一已完成请求无需反复确认空闲。原未知和失败证据与后续裁定一并保留。
