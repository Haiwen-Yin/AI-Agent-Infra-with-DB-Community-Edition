# 访问 IP 限制 v5.0.0

> 当前软件包：**川序社区版**；支持底座：**oracle, pg, yashandb**；版本类别：**Community**；许可：**Apache-2.0**。文中其他底座及企业专属能力用于说明差异，不表示此包包含或支持这些能力。

[English](source-ip-access.md)

入口为 **平台配置 → 能力与策略 → 访问 IP 限制**，所有产品及社区版、企业版均可使用。
读取、预检和保存需要已登录且拥有 `platform.manage` 权限的管理员；写入还会校验 CSRF。
IP 放行不会授予用户或 Agent 任何业务权限，也不会开启人用户注册。

## 配置与验证

新部署或升级后的初始策略为关闭。选择**白名单**时，仅允许匹配的来源；选择**黑名单**时，拒绝匹配的来源。
每行填写一个 IPv4、IPv6 地址或 CIDR 网段，最多 512 条，例如：

```text
192.0.2.10
198.51.100.0/24
2001:db8::/32
```

上述为文档示例地址，使用时应替换为实际访问来源。保存时会规范化网段并去重，不接受域名、端口、区域标识及点分十进制掩码。
IPv4 映射 IPv6 地址按对应的 IPv4 处理。空白名单仅保留本机应急访问；空黑名单不限制来源。
关闭限制会保留已保存的名单，便于后续重新开启。

可以按下面的场景选择起始写法：

```text
# 白名单：办公网和 VPN 出口（仅允许这些网段）
198.51.100.0/24
2001:db8:1234::/48

# 白名单：单台管理机（/32 或 /128 表示单个地址）
192.0.2.10/32
2001:db8::10/128

# 黑名单：只阻断已知问题来源，其他来源仍可访问
203.0.113.0/24
2001:db8:bad::/48
```

这些仍是文档保留地址，不能直接当作真实生产地址。页面中的“预检规则”会展示规范化后的结果和当前识别来源是否仍可访问；确认无误后再填写变更原因并保存。不要把端口、域名或 `http://` 写入规则。

先核对页面显示的当前来源，预检规则，填写变更原因后保存。原因至少 3 个字符，且最多 2000 个 UTF-8 字节；中文通常每字占 3 字节，emoji 通常占 4 字节。三库使用相同的字节上限，超长输入会在写库前被拒绝。如果规则会排除当前来源，页面要求先确认已掌握应急访问方式。
其他管理员已修改策略时，旧版本的保存请求会被拒绝，需要重新读取并核对。
策略修订、规则实体与审计记录在同一事务中提交；页面提供最近 20 次修订记录。
保存进程立即清除缓存，其他进程约 1 秒内刷新生效。

限制覆盖 Dashboard、Portal、登录、注册、静态资源、健康检查、Gateway 接口及 WebSocket 建连。
受限来源统一收到 HTTP 403 和 `Request could not be completed.`，不会显示名单模式、来源 IP 或命中规则。
ASGI 服务不支持 WebSocket 拒绝响应扩展时，使用通用策略关闭消息。
修改规则不会强制断开已建立的长连接或流式请求。数据库策略无法刷新时，外部访问默认拒绝，不会无限沿用过期的放行缓存。

## 本机应急恢复

**始终保留真正从 `127.0.0.1` 直接连接且没有转发头的应急入口，该地址不得加入可信代理范围。**
应急连接仍须正常登录，通过 MFA、CSRF 和权限检查，不能绕过认证。
`::1`、其他 `127/8` 地址及转发头中声称的本机地址均按普通规则处理；名单无法删除该应急例外。

远程被误封时，可在应用主机本机访问，或建立专用 SSH 隧道（替换 SSH 用户、主机及应用端口）：

```bash
ssh -N -L 18000:127.0.0.1:8000 operator@application-host
```

浏览器打开 `http://127.0.0.1:18000/app/`，正常登录后关闭或修正策略。
隧道必须直达应用，不能再经过反向代理。

## 反向代理

正式启动入口使用 `--no-proxy-headers`。自行配置 Uvicorn 服务时也必须保留此参数，确保应用取得原始 TCP 对端。
不支持由 ASGI 服务提前重写 `scope.client` 的方式。

默认不信任来源转发头。需要代理时，在应用服务环境变量 **`CX_TRUSTED_PROXY_CIDRS`** 中填写代理的明确地址或 CIDR，逗号分隔并重启服务。
此信任范围由主机运维管理，不允许通过页面修改。例如：

```bash
export CX_TRUSTED_PROXY_CIDRS='192.0.2.5/32,2001:db8:1::5/128'
./start_web_server.sh start
```

边缘代理应使用实际观察到的客户端地址覆盖传入的 `X-Forwarded-For`。
多级代理从右向左剥离可信节点，遇到非可信节点即停止。
可信代理必须提供唯一、有效且长度受限的该请求头；缺失或格式错误时拒绝访问。
本机代理应绑定其他来源地址，例如通过 Nginx `proxy_bind` 使用 `127.0.0.2`，并明确登记该代理地址。
可信代理范围如果包含 `127.0.0.1`，服务会拒绝启动；声称应急直连却携带转发头的请求也会被拒绝。
未声明且完全移除转发信息的本机代理无法与真正本机连接区分，应限制后端监听和访问路径，避免客户端绕过指定代理。
不要把整个客户端网段设为可信代理。

健康探针同样受规则限制，应放行其来源或使用直接本机应急连接。
本功能不能替代主机/网络防火墙及数据库自身的访问控制。

## 接口与数据库实体

- `GET /api/platform/ip-access`：当前策略、识别来源与近期历史。
- `POST /api/platform/ip-access/preview`：返回规范化规则及当前来源是否可继续访问，不写入数据库。
- `PUT /api/platform/ip-access`：参数为 `enabled`、`list_mode`（`ALLOWLIST` 或 `DENYLIST`）、`rules`、`expected_revision` 及至少 3 字符且最多 2000 个 UTF-8 字节的 `reason`。

三种适配器使用一致的增量迁移 `102_v5_0_0_network_access.sql`，新增 `CX_IP_ACCESS_STATE`、
`CX_IP_ACCESS_REVISIONS`、`CX_IP_ACCESS_RULES` 三个数据库实体。修订和规则历史不可变，普通 Agent 数据库会话无权读写。
已应用的历史 SQL 保持原值；启动新代码前须升级并校验所选底座。
