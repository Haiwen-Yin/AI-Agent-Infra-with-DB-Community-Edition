# v5.0.0

## English

- Add database-backed IPv4/IPv6 allowlist and denylist configuration, individual IP/CIDR rules, atomic audit, direct 127.0.0.1 recovery and generic source rejection across web entry points.
- Deliver one Chuanxu Community package with an explicit choice of Oracle,
  PostgreSQL or YashanDB; shared business code remains a single implementation.
- Deliver OpenTenBase AgentX as an independent PostgreSQL-only Community product.
- Use the official OpenTenBase emblem beside the separate `OpenTenBase AgentX`
  name throughout its Dashboard, Portal and authentication pages.
  Authentication footers show only the version; product branding omits database edition labels.
- Retain separate Oracle, PostgreSQL and YashanDB Enterprise packages.
- Validate product identity, database selection, selected-driver installation,
  deployment baselines and migration routing from the same product registry.
- Retain database-entity task continuity, collaboration, memory, knowledge,
  DB4A2A, authorization and audit behavior across the new delivery structure.
- Refresh product-specific bilingual guides and built-in product Knowledge,
  preserving user-edited historical content and stable technical identifiers.
- Fix duplicate Principal selectors, portable task identity creation and
  DB4A2A digest storage; probe only selected backends in POC readiness checks.
- Keep Channel inspection read-only when the current user is not a member or
  the Channel is inactive, without weakening server-side authorization.
- Preserve language and theme choices across Dashboard, Portal and work
  continuity pages, including navigation and reloads from legacy preferences.
- Keep model/provider evidence tied to exact profile revisions. Registered MCP,
  bounded A2A and pinned frameworks remain governed; arbitrary frameworks,
  effect replay and live Graph migration remain disabled.
