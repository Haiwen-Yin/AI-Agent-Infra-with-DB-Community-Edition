# v5.0.3 release notes / 版本说明

## English

- Knowledge answers and Task context combine applicable database relational,
  full-text, vector, tag and bounded graph signals. Ranking uses database
  queries and deterministic fusion without additional generation requests.
  Available signals depend on the selected backend and its current readiness;
  retrieval scores never grant access or establish factual certainty.
- Guided intake records purpose, source, responsibility, product/version/time
  applicability, classification and audience. Preview and quality feedback
  precede the existing candidate, independent review and publication process.
  Upload or import alone does not publish shared Knowledge.
- Source-bound learning topics support Human onboarding and metadata-first
  Agent capability discovery. Readers load exact content by digest. Product
  identity, backend and edition scope remain explicit; reading a guide or Skill
  does not grant execution authority. Incremental publication preserves prior
  snapshots and user-edited content.
- Community and OpenTenBase AgentX retain learning entrypoints but exclude the
  nine complete learning units from their software archives. Matching optional
  JSON companions can be explicitly imported by an authorized administrator.
  Enterprise retains automatic deployment; upgrades preserve installed knowledge.
- Knowledge and Memory context retain original source authority and exact
  revisions. Task, Work, Handoff and Graph receipts distinguish planned work
  from actual execution. Required constraints and exceptions must fit the
  context budget; an insufficient budget blocks dispatch.
- Additive migrations maintain native intake enforcement and backend-specific
  retrieval support. Migration 117 adds nullable Task Step start/completion
  times without inventing timestamps for historical steps. Use this product's
  packaged baseline and supported migration chain.
- Oracle migration 118 makes the child document key explicit so collaboration
  Duality Views can be recreated with all existing JSON fields after restore.
  The original primary key, application rows and grants are preserved.

Use the selected product's deployment and migration guides for a fresh install
or a supported upgrade, and verify readiness before enabling a workflow.
Query embeddings, context and answer generation retain their own costs even
though ranking adds no generation call. Check model answers against the exact
sources; retrieval alone establishes neither factual accuracy nor completion.
Customer database versions, prerequisites, upgrade sources, model capability
and capacity require verification for the actual deployment.

## 中文

- 知识回答与 Task 上下文结合适用的数据库关系、全文、向量、标签及有界图关系
  信号，通过数据库查询和确定性融合排序，不额外请求生成。可用信号取决于所选
  底座及当前就绪状态；检索得分不授予权限，也不证明事实必然正确。
- 引导入库记录用途、来源、责任人、产品/版本/时间、密级及受众。预览和质量
  反馈衔接已有候选、独立审核及发布流程，上传或导入成功不会自动发布共享知识。
- 有来源的学习主题支持人用户入门及 Agent 先发现元数据、再按摘要加载精确
  正文。资料明确产品、底座和版本类别，阅读手册或 Skill 不授予执行权限。
  增量发布保留旧快照及用户修改内容。
- 社区版和 OpenTenBase AgentX 保留学习入口，软件包不携带九个完整学习单元。
  有权管理员可按需导入独立提供的匹配 JSON 文件。企业版继续自动部署；升级
  保留数据库中已经安装的知识。
- 知识与 Memory 上下文保留原始来源权限和精确修订。Task、Work、Handoff 与
  Graph 回执区分计划和实际执行；必要约束及例外不能因预算不足被截掉后继续
  发送，预算不足时阻止派发。
- 增量迁移维护原生入库规则和底座特定检索支持。迁移 117 增加可空的 Task Step
  开始/完成时间，不伪造历史时间。升级应使用当前产品包内基线及受支持迁移链。
- Oracle 迁移 118 明确子文档键，使协作组 Duality View 在恢复后可按原有全部
  JSON 字段重新创建，保留原主键、业务数据和授权。

新装和受支持的升级均应遵循所选产品的部署与迁移指南，启用工作流前核对
当前就绪状态。排序不增加生成调用，查询向量、上下文及回答生成仍有各自
成本。模型回答须结合确切来源核对，不能由检索命中推定事实正确或任务完成。
客户数据库版本、部署前提、升级来源、模型能力与容量须按实际部署分别验证。
